# Landing Page Design
Inspect the smallest relevant README or product brief first. Identify name, purpose, audience, actual capabilities, primary CTA and tone. Derive sections from those facts. When sources are unavailable, use the user's facts and state gaps; never substitute a different product.
Do not invent testimonials, customers, user counts, latency, uptime, prices or certifications. Pricing requires real supplied pricing or explicitly requested placeholders. Avoid automatic purple gradients, glass cards, floating orbs and generic SaaS copy unless the user requests that style.
Choose a deliberate direction appropriate to the product: editorial, technical, industrial, light, dark, minimal or experimental. Establish a small token set for colors, type, spacing and radii. Give the hero one strong message and one primary CTA. Use readable text measure, clear contrast and intentional mobile composition.
Keep the implementation lightweight. Finish actual interactions and all requested files. Inspect mobile and desktop screenshots when the runtime supports them; technical PASS alone does not prove visual quality.
